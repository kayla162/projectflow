>
> 本專案為 4 人團隊專題，原始 repo 為 [chenliyu0410/projectflow](https://github.com/chenliyu0410/projectflow)。
> 這裡是完整複製的版本，保留所有分支與每個 commit 的原作者紀錄。
>
> **我（[kayla162](https://github.com/kayla162)）的負責範圍：OCR 與 n8n 自動化**
> - **OCR**：掃描頁前處理 ＋ RapidOCR，切成 RAG 段落；辨識正確率 91.7%
> - **自動化**：自架 n8n，建立 4 條排程（通知、每日摘要、AI 週報、備份與到期提醒）
> - **手寫表單 OCR（評估階段）**：座標定位每個欄位，手寫交給 OvisOCR2、打勾框用筆跡比例判斷；繁中手寫欄位正確率 32.8% → 71.1%，打勾框 0% → 90.1%，拿不準的送人工確認。見[成果報告](docs/ocr-handwriting-forms-report.md)

以「專案」為核心的 AI 工作流系統。專流把階段、任務、審核、文件和 AI 助手放在同一個地方，整套系統裝在公司自己的主機上，資料不出公司。

> 內建 6 家虛構公司、39 個專案、約 80 個帳號的展示資料，啟動後就能直接登入操作。

## 1. 解決什麼問題

中小型製造業（例如食品、寵物食品研發）的新品開發，常常靠 Excel 和 LINE 追進度。這樣做會遇到四個問題：

| 痛點 | 會發生什麼 | 專流怎麼解決 |
|---|---|---|
| 漏掉步驟 | 少一個審核節點，後面就一路跟著錯，例如罐標沒人校對就送印 | 套用流程模板，自動排好階段和任務；前一關沒通過，下一關自動鎖住 |
| 文件靠手打 | 報價單、工單每次重打，金額和稅額容易算錯 | 用公司的 Word 樣板，只填必要欄位；金額和 5% 營業稅自動算好，產出後存成文件版本 |
| 找不到資料 | 規範、會議紀錄散在各處，只能問人 | AI 助手在公司主機上查文件，回答附出處；只查得到自己有權限的文件 |
| 經驗留不下來 | 這次踩過的坑，下個專案又踩一次 | 把教訓補成新節點，另存成新版流程模板，下個專案直接套用 |

跟 Notion 這類雲端工具最大的不同是：**資料和 AI 都留在公司內網**，配方、價格這些機密不用交給外部服務。

## 2. 簡易動畫

![專流操作示範：套用模板建立專案、AI 助手附出處回答](docs/media/demo.gif)

約 5 秒的示意動畫，依序是：

1. **建立專案**：選公司的流程模板，一次排好所有階段。
2. **AI 助手**：用白話提問，AI 查公司文件回答，並附上來源。

## 3. 用了哪些技術？為什麼？

| 層 | 技術 | 為什麼選它 |
|---|---|---|
| 前端 | React 19＋TypeScript、Vite | 元件化好維護，型別檢查能擋掉低級錯誤，建置快 |
| 網頁伺服器 | nginx | 提供前端靜態檔，並把 `/api/` 轉給後端；前後端同網域，不用處理 CORS |
| 後端 | FastAPI（Python 3.13）、SQLAlchemy 2 | 自動做型別驗證、產生 API 文件；Python 方便接 AI 和 OCR |
| 資料庫 | PostgreSQL 17＋Alembic | 交易、外鍵和約束可靠；用 migration 逐版升級，不必重設資料 |
| AI 問答 | Ollama（Qwen3 4B）、bge-m3、SQLite FTS5／BM25 | 模型跑在本機或內網，資料不出公司；關鍵字和語意混合檢索，換個說法也找得到 |
| 文件辨識 | RapidOCR（繁體中文模型）；手寫表單評估 OvisOCR2 | 不用連網；掃描 PDF 和圖片也能讓 AI 查到。潦草手寫交給端到端視覺模型 OvisOCR2，讀得比傳統 OCR 準（評估階段） |
| 自動化 | n8n（地端自架）＋Mailpit | 排程交給現成工具，資料、權限和稽核仍留在專流 |
| 部署 | Docker Compose | 所有服務、版本和設定寫在同一個檔案，換一台機器，一個指令就是同樣的環境 |
| 測試與 CI | pytest、Vitest、Playwright、GitHub Actions | 後端、前端、真瀏覽器三層各自驗證，推到 main 或開 PR 時自動跑 |

選型理由和各功能對應的程式檔，詳見[技術架構說明](docs/technical-roadmap.md)。

## 4. 架構

![專流架構：一台 Windows 主機上的 5 個 Docker 容器，加上只在本機執行的 AI 模型](docs/media/architecture.svg)

整套系統裝在一台 Windows 主機上，不連外網。圖上的三個重點：

| 區塊 | 說明 |
|---|---|
| 後台 API | 所有請求都要經過它：先檢查帳號權限，再處理專案、任務等業務。AI 閘道也在這裡，負責問答、資料分析和 OCR |
| Docker＋本地 AI 模型 | 5 個容器和 AI 模型（Ollama 跑 qwen3 4B）都在這台主機上，問題和資料不會送到雲端 |
| 自動化排程 | n8n 負責寄通知、每日摘要、週報和每日備份，只透過 API 存取資料，不直接碰資料庫 |

附件、AI 索引和資料庫都存在 Docker volume，關掉或重建容器都不會不見；每日備份另外寫到主機的 `backups/` 資料夾。

## 5. 工程亮點

| 要解決的問題 | 我們的做法 | 結果 |
|---|---|---|
| AI 可能說出使用者沒權限看的內容 | 先過濾權限，才把文件交給 AI | 沒權限的文件，AI 看不到 |
| AI 自己寫 SQL，可能查錯或亂查 | AI 只能從 16 種內建查詢模板挑一種 | 不會執行任意 SQL |
| 換個說法問，就找不到文件 | 關鍵字＋語意混合搜尋 | 找到正確文件的比率從 0.49 提升到 0.94 |
| 機密資料不能送到雲端 | AI 模型只在本機或內網執行 | 資料不出公司 |
| 業界表單手寫潦草、要判斷有沒有打勾，整頁 OCR 讀不出來 | 用座標定位每個欄位；手寫交給 OvisOCR2，打勾框用筆跡比例判斷，拿不準的送人工 | 手寫欄位正確率 32.8% → 71.1%；打勾框 0% → 90.1%，只有 1.5% 判錯沒被發現（評估階段，尚未接進產品） |
| AI 寫週報時，數字可能算錯 | 數字由程式計算，AI 只寫文字；句中出現資料裡沒有的數字，那一段自動改用系統條列，負責人確認後才寄出 | AI 自己換算的數字寄不出去 |
| 資料被改了，查不到是誰改的 | 每筆修改都和稽核紀錄一起寫入 | 每一筆變更都查得到 |
| 改程式時怕把功能弄壞 | 約 1,000 個自動測試，推到 main 或開 PR 時自動執行 | 改壞了馬上就會發現 |

## 6. 快速開始

需要 Python 3.13 和 Docker Desktop（Linux 容器）。在 repo 根目錄執行：

```powershell
python deploy/start.py --seed-demo   # 第一次：建立示範帳號和資料
python deploy/start.py               # 之後啟動：保留資料，不要再加 --seed-demo
```

打開 <http://127.0.0.1:15173>，用公司 `food`、帳號 `yu`、密碼 `demo-yu` 登入。

- **通知、週報和每日備份**：第一次照 [deploy/n8n](deploy/n8n/README.md) 設定 n8n，之後 `start.py` 會自動一起啟動。
- **其他用法**：開放給同網路或外部的人使用、可攜展示包、自動驗收、單檔 Demo，都寫在[安裝與開發指南](docs/getting-started.md)。

> 不要執行 `docker compose down -v`，也不要刪除 volume，否則資料庫和附件會一起被清掉。
